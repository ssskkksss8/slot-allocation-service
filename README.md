# Дипломная работа

**Система приоритизированного распределения ограниченных ресурсов при высокой конкурентной нагрузке**

Проект реализует сервис бронирования авиабилетов, в котором заявки на ограниченное число мест обрабатываются не только по времени поступления, но и по вычисляемому приоритету пользователя. Такой подход позволяет устойчиво обрабатывать всплески спроса, предотвращать перепродажу мест и распределять ресурс в пользу наиболее ценных для системы клиентов.

## Основные возможности

- регистрация и авторизация пользователей с JWT;
- поиск рейсов и отправка заявок на бронирование;
- асинхронная обработка заявок через RabbitMQ;
- приоритизация пользователей по поведенческим и финансовым признакам;
- защита от oversell при конкурентной нагрузке;
- личный кабинет пользователя с билетами, заявками, балансом и уведомлениями;
- административные разделы для управления городами, аэропортами и рейсами;
- демонстрационные панели с архитектурой, метриками и сравнением FIFO/Priority Queue;
- JMeter-сценарии для проверки поведения под нагрузкой.

## Архитектура

Система состоит из нескольких сервисов:

- `app` - backend на Spring Boot;
- `hilbert-frontend` - frontend на React и Vite;
- `postgres` - основная реляционная база данных;
- `rabbitmq` - брокер сообщений для обработки заявок;
- `load-test` - сценарии нагрузочного тестирования.

Backend принимает пользовательские запросы, сохраняет заявки и публикует события в очередь. Обработчик очереди рассчитывает приоритет, проверяет доступность мест и фиксирует результат бронирования в транзакции. Frontend предоставляет пользовательский и административный интерфейс.

## Запуск через Docker Compose

Перед запуском можно задать переменные окружения в `.env`:

```env
DB_USER=db_user
DB_PASSWORD=db_password
RABBITMQ_USER=guest
RABBITMQ_PASSWORD=guest
JWT_SECRET_KEY=replace_with_base64_encoded_secret
```

Запуск:

```bash
docker compose up --build
```

После запуска:

- frontend: `http://localhost:3000`;
- backend API: `http://localhost:8081`;
- RabbitMQ Management: `http://localhost:15672`;
- PostgreSQL: `localhost:5432`.

## Тестовые данные

Начальные данные для базы находятся в `seed_test_data.sql` и `docker/postgres-init/init.sql`. Они используются для демонстрации сценариев бронирования, ролей пользователей, рейсов, баланса и истории заявок.

Файлы `users.csv` и `load-test/users.csv` содержат демонстрационные учетные записи для нагрузочного тестирования. Эти данные не предназначены для продуктивной среды.

## Нагрузочное тестирование

В проекте есть два JMeter-сценария:

- `high_load_test.jmx` - базовый сценарий высокой конкурентной нагрузки;
- `load-test/priority_booking_load_test.jmx` - сценарий проверки приоритетной очереди.

Пример запуска JMeter из корня проекта:

```bash
jmeter -n -t high_load_test.jmx -l results.jtl
```

Для сценария из каталога `load-test`:

```bash
cd load-test
jmeter -n -t priority_booking_load_test.jmx -l results.jtl
```

## Проверка

После запуска можно проверить основные сценарии:

1. Зарегистрировать пользователя или войти под тестовой учетной записью.
2. Найти доступный рейс.
3. Отправить заявку на бронирование.
4. Проверить результат в разделе заявок, билетов и уведомлений.
5. Для администратора создать или отменить рейс и проверить обновление статусов.

## Назначение проекта

Проект демонстрирует подход к распределению ограниченных ресурсов в условиях высокой конкурентной нагрузки. В отличие от простой FIFO-очереди, система использует приоритетную модель и асинхронную обработку, что позволяет повысить устойчивость сервиса и качество итогового распределения.
